The idea

Cryptography hides what a message says. Steganography hides that a message exists at all. A stego image looks like an ordinary photo to anyone who receives it.

Least significant bit (LSB)

Each pixel stores red, green and blue as a number from 0 to 255. Changing the last bit shifts a channel by 1 out of 256 - far below what an eye can see. That spare bit is where the message goes.

Type a character to watch it happen:

one character = 8 bits = 8 colour channels

How much fits

width x height x 3 channels x bits per channel / 8 = bytes

A 12 megapixel photo holds roughly 4.5 MB at one bit per channel - far more text than anyone needs. Using 2 or 3 bits multiplies capacity but the noise starts to become visible in flat areas like skies.

Why PNG and not JPEG

PNG is lossless: every pixel value survives a save. JPEG throws away detail it thinks you cannot see, and the last bit of each channel is exactly what it discards first. You can load a JPEG here, but the output has to be PNG.

Sequential vs scattered

Sequential fills channels in order from the top-left. It is simple and it is also the first thing an analyst looks for - the change is a solid block at the start of the image.

Scattered spreads the bits across the whole image using gaps derived from your passphrase. Without the passphrase the positions are unknown, and the changes look like ordinary sensor noise rather than a block.

The position sequence is stretched from the passphrase with PBKDF2, the same way the encryption key is, so guessing positions costs an attacker the same work as guessing the key. Even so, scattering hides the shape of the data rather than its contents - keeping it secret is the encryption's job.

Layer encryption underneath

Hiding is not protecting. Anyone who guesses the method reads the message. With a passphrase set, steg-lab encrypts with AES-GCM (PBKDF2-SHA256, 150k iterations) before embedding, so extracting the bits gives an attacker nothing but noise.

Hardened mode

Select "hardened" from the placement dropdown. Two things change versus standard mode:

  • LSB matching. When a channel's last bit already matches the message bit, the pixel is left untouched. When it does not, the value is nudged +1 or -1 at random rather than forced to the target. Chi-square and Sample Pair Analysis detect the value-pair imbalance that LSB replacement creates; LSB matching does not produce that imbalance, so those attacks find nothing.
  • No plaintext header. There is no magic string, no bit-depth byte, no length field in the clear. A random 16-byte salt sits in the first 128 channels and feeds one PBKDF2-SHA256 derivation (150k iterations) that yields two AES-256-GCM keys plus a scatter seed. The payload length is stored as its own AES-256-GCM ciphertext in the next 256 channels; the payload itself is encrypted and scattered across the rest of the image using the keyed seed. A decoder with the wrong passphrase gets an authentication-tag failure, the same result as an image with nothing hidden in it. There is nothing to grep for.

Note on placement: the salt and length blocks live at fixed positions so they always survive embedding, and the payload is scattered by the passphrase-derived seed. This spreads the message across the whole frame without a fixed pattern, but it is content-blind - it does not steer bits toward busy regions, because any content-based ordering shifts when embedding perturbs the pixels and would not be reproducible on decode.

The trade-off: a passphrase is mandatory, and a receiver who does not have it cannot even confirm a message exists. That is usually the point.

How hidden messages get caught

  • Bit-plane view - isolate the lowest bit and look for static where structure should be. The Reveal tab does this.
  • Chi-square and RS analysis - LSB embedding pushes the counts of value pairs (0/1, 2/3, 4/5 ...) toward equal, which is statistically odd for a real photo.
  • File size and history - a 4 MB PNG of something that should have been a 400 KB JPEG raises questions on its own.
  • Comparison - if the original image exists anywhere, a diff ends the discussion immediately.

Other techniques worth knowing

  • Scattered LSB with a keyed position sequence - both the scattered and hardened modes here. Adaptive/content-aware placement (steering bits into busy regions) is a real technique too, but it needs the cover and stego images to agree on an ordering the embedding does not disturb - harder than it looks, and out of scope here.
  • DCT coefficient embedding (JPEG) - hides data in frequency coefficients instead of pixels, so it survives JPEG compression. F5 and OutGuess work this way.
  • Palette manipulation in GIF/PNG-8 - reorder or nudge palette entries rather than pixel data.
  • Metadata fields - EXIF comments, PNG tEXt chunks. Trivial to do, trivial to find, and stripped by most upload pipelines.
  • Alpha channel embedding - works, but transparency is rare and often mangled by browsers and editors, so it is fragile.
  • Audio and video - LSB in PCM samples, echo hiding, phase coding.

Format used here

A 9-byte header goes in first, sequentially: STG1 magic, one flags byte (bit depth, scattered, encrypted), then a 4-byte length. The payload follows. The reader tries bit depths 1 to 3 and checks the magic, so nothing has to be remembered except the passphrase.

Note the trade-off: the header itself is always sequential and unencrypted. That is what makes decoding effortless, and it also means the tool announces itself to anyone who looks for that magic. Real covert channels do not include a signature. Hardened mode has no header - it uses an AES-GCM tag failure to signal 'wrong passphrase or no message', with no other distinguishing feature.
